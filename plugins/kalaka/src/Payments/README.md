# Payments

The payments port and the system use cases that record what a payment provider reports.

`Api/` holds the port, `PaymentProvider` (`id()`, and `accepts()`, `payUrl()` and `latestOf()`, each taking one `PaymentProviderInput`, built with `forStart(request, returnUrl)` or `forLookup(key, currency)`; `AbstractPaymentProvider` is the base to extend, with `latestOf()` answering null), contributed with `Contributions::paymentProvider()` and read through `PaymentProviders::active()` (the first one contributed), and its values: `PaymentRequest`, `RequestLine`, `OpenPayment` (state, since, and the request's ref), `OpenPaymentState` (`Paid`: paid and not yet recorded), `RegistrationRef` (the `12:47K3` form). `CardPayments::start()` runs the use case `kalaka-portal/start-card-payment` (`StartCardPayment`, which checks what is payable now and builds the one-line request, for the whole payable amount or for the `amount` the registrant asks for, between the limits of `CardAmountLimits`) and then asks the provider for the pay URL, outside the transaction, under a named lock per registration (the provider is asked `latestOf()`, `accepts()` and `payUrl()` there and never in the use case). `OnlinePayments` is what a provider reports to: `recordPaid()` and `recordRefunded()` run the system use cases `kalaka/record-online-payment` and `kalaka/record-online-refund` (`RecordOnline`), which write one `payment` or `refund` ledger line per item, once, never gated. `CardAmountLimits::of($full)` is the one place of the amount's limits (the maximum is the payable amount; the minimum is the site option `kalaka_card_minimum`, a map of currency to decimal text, `{"HUF": "1000"}` when absent, or the payable unit; never above the payable amount). Refusals: `CardAmountRefused` (`kalaka_card_amount_refused`, carrying `min` and `max`), `CardPaymentUnavailable` (`kalaka_card_payment_unavailable`), `CardPaymentInFlight` (`kalaka_card_payment_in_flight`) and `NoPaymentProvider` (`kalaka_no_payment_provider`). `PaymentsInFlight` is the one rule of whether the latest request is money on its way (processing, or paid and not recorded), read by the start, and from #252 (part 3) by the portal's status read too. `OnlineRefs` holds the ref patterns of a report (one source for the checks and the schemas) and checks a report: its refs, and that each item ref is named once.

Entry points: `Api\CardPayments` (the portal's `POST kalaka-portal/v1/card-payment` calls it), `Api\OnlinePayments`.
